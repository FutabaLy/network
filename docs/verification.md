# 验证说明（导出前后都做了检查）

本片的所有画面元素都由 `src/sim.ts` 的参数算出，因此验证分三层：**数值自检 → 代表帧逐张检查 → 成片属性复核**。

## 1. 数值自检：`npm run check:sim`

把全片用到的每个数字与关键时刻重算一遍，30 项断言，全部通过：

```
— 统一参数 —
  ok  R = 8e6 bit/s        ok  L = 8000 bit        ok  Tp = 12 ms
  ok  Tf = L/R = 1 ms      ok  R×Tp = 96000 bit = 12000 B = 12 帧
  ok  RTT = 2Tp = 24 ms    ok  周期 Tf+2Tp = 25 ms
  ok  序号空间 = 32        ok  GBN 最大窗口 = 31   ok  SR 最大窗口 = 16
  ok  Wmin = ceil(25/1) = 25
  ok  U(停止等待) = 4%     ok  U(16) = 64%         ok  U(25) = 100%（封顶）

— 关键时刻 —
  ok  末比特进入链路 = 1 ms       ok  首比特到达 B = 12 ms
  ok  整帧接收完成 = 13 ms        ok  ACK 回到 A = 25 ms

— 一帧在链路中的位置（0 = A 出口，1 = B 入口）—
  ok  t=0 ms   尚未进入链路
  ok  t=0.5 ms 只进入一半（首比特位于 1/24）
  ok  t=1 ms   末比特刚进入链路（tail = 0），首比特位于 1/12
  ok  t=12 ms  首比特到达 B，但整帧尚未收完
  ok  t=13 ms  末比特到达 B，整帧接收完成，链路中已无该帧

— 持续发送时链路上的在途帧数（第 4 段）—
  ok  t=6 ms 在途 6 帧      ok  t=12 ms 在途 12 帧（链路刚好填满）      ok  t=13 ms 稳态 12 帧
```

这一层直接对应题目的两条准确性要求：**数据帧必须逐比特进入链路**（t=0.5 ms 时只进一半）、**区分首比特到达 / 末比特到达 / ACK 返回**（12 ms vs 13 ms vs 25 ms）。

抽帧      : out/verify/shot1..6.png → 已复制到 docs/frames/（1 / 26 / 38 / 55 / 68 / 88 s，逐张看过）

抽帧复核要点：88.0 s 那帧正好是第 6 段的结论卡 + 字幕「GBN 最大 31，SR 只有 16。」——与 `src/narration.ts` 里 `s6_4` 的时间点（85.6 s 起，实测 3.6 s）吻合，说明**旁白、字幕、画面三者同步**。

## 5. 字幕与旁白

- 24 条中文旁白由 edge-tts（`zh-CN-XiaoxiaoNeural` 音色，语速 +12%）逐条合成，实测时长写入 `audio/narration/durations.json`；
- 画面里的字幕层（`src/components/Subtitles.tsx`）与导出的 `subtitles/narration.srt` **同源**（都读 `src/subs.ts`），所以不存在「视频字幕与 SRT 不一致」的问题；
- 每条旁白的结束时间都做了余量检查：六个分镜中最紧的是第 5 段（末条 14.82 s，仍在 15 s 内），其余余量 0.5–1.9 s。
